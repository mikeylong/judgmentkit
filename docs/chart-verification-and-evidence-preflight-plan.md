# Chart verification and evidence preflight plan

JudgmentKit should help an implementing agent submit usable review evidence and catch chart defects that prevent a person from reading the requested information. Completion means malformed packets receive precise corrections before substantive review, and the Tide chart with overlapping labels fails while its repaired version passes every required snapshot.

The next work follows the activity-first contract in [DESIGN.md](../DESIGN.md) and the implementation requirements in [the AI UI generation contract](../contracts/ai-ui-generation.activity-contract.json). The completed local [activity and routing changes](../specs/activity-routing-reliability.md) remain a separate change set. This document proposes the next work; it adds no runtime behavior.

The activity is implementation review. Mike supplies the intended outcome and governing sources. The implementing agent generates the interface, assembles evidence, and repairs defects. JudgmentKit checks evidence structure and measures supported rendered relationships. For the Tide reader, choosing a location and day should make the supplied measurements, extremes, and 24-hour chart readable. Diagnostic fields belong in the agent's review results.

1. **High: validate evidence before substantive review.** Add a shared preflight validator and a public `preflight_ui_implementation_candidate` entry point. Derive allowed primitives, component and pattern ids, required states, submission fields, and active composition rules from the implementation contract. Return field paths, error codes, expected shapes, and repair examples for malformed arrays, unsupported ids, missing control declarations, and invalid manifest fields. Distinguish missing or malformed evidence from well-formed submissions that fail a requirement. Reuse the existing evidence-field mapping to produce a minimal template; keep that template and the validator generated from the same definitions.

   Run cheap structural checks before browser work. During browser inspection, validate selector syntax, resolution, uniqueness where required, and the governed element type. A field-select declaration pointing at a wrapper must identify the native select or the supported custom-control parts. Reuse one capture for selector diagnostics and review measurements. A structural preflight success means the packet is ready for browser inspection and substantive review. Only implementation review can accept the candidate.

   Attempt accounting remains with the calling agent or wrapper. Document that a rejected preflight does not submit an implementation review; do not mutate `current_attempt`. Give runtime-unavailable results a distinct retryable code, and document transport retry handling without claiming a durable server-side attempt ledger.

2. **High: make chart readability an explicit review requirement.** Add an SVG chart contract in the composition adapter for activities that depend on reading plotted information. Declare the plot region, text roles, clipping boundaries, and required snapshots. Require measurement when the reviewed activity depends on the chart; an omitted manifest or false no-applicability declaration must not suppress the check. Keep domain-specific values and expectations in the product fixture.

   Extend the existing trusted browser runtime to detect visible label collisions and clipped text after fonts settle. Calibrate text geometry against rendered SVG examples so bounding-box intersections do not reject harmless whitespace. Support explicit, bounded relationships for intentional annotations; a blanket overlap exemption is insufficient. Include readable units and an accessible representation of the plotted information in the contract checks. Preserve the existing rules for chart contrast and semantic fallback.

3. **High: report the exact chart coverage.** Bind measurements to the candidate, contract, rendered document, snapshot identity, viewport, and source-data hash where applicable. Report measured, caller-declared, and untested states separately. The first release measures self-contained SVG snapshots using the existing script-blocking renderer. Missing required snapshots, ambiguous chart targets, or unsupported Canvas/WebGL content produce `review_required` for chart verification.

   Static snapshots do not prove that location and day controls update the live application correctly. Add fixture-backed value checks for the supplied measurements and extrema, and retain a separate application-level test for actual selection behavior. A later interactive verifier requires its own execution and trust design. Artifact Inspector's deferred interactive attestation remains outside this work.

4. **High: prove the changes with the Tide failures and nearby cases.** Preserve the experiment logs. Create local fixtures with source hashes for malformed evidence, wrapper selectors, the accepted chart before label repair, and the repaired chart. Verify the original collision case fails and the repaired chart passes all 56 required snapshots: 14 locations, two days, and two viewports. Record collision and clipping results for each snapshot rather than collapsing coverage into a desktop/mobile flag.

   Add negative cases for omitted charts, invalid selectors, hidden labels, stale receipts, missing snapshots, data that differs from the supplied fixture, unsupported renderers, and false no-applicability claims. Include a harmless bounding-box intersection and an intentional annotation to test false positives. Follow [the local testing skill](../skills/write-tests/SKILL.md). Run affected kernel and browser tests for each increment, then the full suite and MCP compatibility checks after the contract and API changes are integrated.

5. **Medium: verify that the agent workflow improves.** After deterministic regressions pass, run a fresh, bounded generation trial with a pinned runtime, model settings, brief, data, and budget policy. Capture tool calls, malformed submissions, substantive review attempts, repair time, user questions, request bytes, and final task checks. Include independent chart inspection before delivery. Reused screenshots do not count as new trials. A single trial can demonstrate that the revised workflow completes this task; broader quality claims require repeated comparisons.

6. **Medium: deliver two reviewable increments.** Implement evidence preflight first, including kernel, CLI/MCP exposure, submission templates, portable guidance, and regressions. Implement the SVG chart contract and measured coverage second, including trusted receipts, negative fixtures, and the 56-snapshot replay. Update the [agent usage contract](agent-usage-contract.md) and [daily workflows](daily-agent-workflows.md) alongside each increment. Keep existing activity/routing edits intact and report acceptance results, unsupported cases, and test evidence for each increment.

The first increment is done when malformed Tide packets receive specific preflight corrections and valid packets continue through the existing acceptance review. The second is done when the chart before label repair cannot pass, the repaired chart passes every required measured snapshot, and missing or unsupported evidence remains visible in the result. The fresh trial then checks whether those capabilities reduce repair effort in an actual generation workflow.
